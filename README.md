# SemEval-2026-Task13-Subtask B  
Multi-Class LLM Family Attribution for Source Code

## Task Overview

This repository contains our solution for **SemEval Code Attribution Subtask B**, a fine-grained multi-class classification challenge.

Given a code snippet, the objective is to predict whether it is:

- Fully human-written (label 0)
- Generated by one of 10 LLM families:
  - DeepSeek-AI
  - Qwen
  - 01-ai
  - BigCode
  - Gemma
  - Phi
  - Meta-LLaMA
  - IBM-Granite
  - Mistral
  - OpenAI

This is a **11-class classification problem**.

---

## Motivation

Accurate attribution of code origin is critical for:

- Academic integrity verification
- Hiring process validation
- AI dataset curation
- Cybersecurity risk assessment

Subtask B extends beyond binary AI detection to **fine-grained LLM family attribution**.

## Dataset Description

Files provided by the organizers:

- `train.parquet`
- `validation.parquet`
- `test.parquet`
- `test_sample.parquet`
- `sample_submission.csv`

### Columns

| Column     | Description |
|------------|------------|
| code       | Source code snippet |
| generator  | Generator model name or "human" |
| language   | Programming language |
| label      | 0 = human, 1–10 = LLM families |

Dataset size:
- Train: 500,000 samples
- Validation: 100,000 samples
- Test: 500,000 samples

---

## Approach

### 1️. Handling Severe Class Imbalance

Human-written samples dominate the dataset:

```
Human (label 0): 442,096
Minority classes: ~4K–10K each
```

We downsampled the majority class:

```
KEEP_MAJ = 80,000
```

Final balanced training size ≈ 160K samples.

---

### 2️. Text Representation Strategy

Each input sample is constructed as:

```
<language> + " " + first 800 characters of code
```

This helps the model capture language-specific generation patterns.

---

### 3️.  Model Architecture

We fine-tuned:

```
microsoft/codebert-base
```

- Max tokens: 256
- Batch size: 8
- Optimizer: AdamW (lr = 2e-5)
- Scheduler: Linear warmup (10%)
- Mixed precision (AMP) enabled
- Epochs: 3

## Key Design Decisions

- Downsampling majority instead of oversampling minorities
- Language prefix inclusion
- Token truncation to 800 characters (prevent memory explosion)
- Mixed precision training for GPU efficiency
- Macro F1 optimization due to class imbalance

---

## Observations

- Human vs LLM discrimination was relatively strong.
- Attribution between similar LLM families (e.g., LLaMA vs Mistral) remains challenging.
- Model performance dropped significantly in unseen generator setting.

---

## Future Improvements

- Hierarchical classification (Human vs AI → Family)
- Class-weighted loss instead of downsampling
- Longer context models (e.g., CodeLLaMA)
- Ensemble methods
- Language-specific fine-tuning
